# 成长 / 发育机制问答接入说明

## 已支持的问题

- 哪些可发育？
- 哪些棋子可发育？
- 哪些棋子可成长？
- 哪些羁绊可发育？
- 哪些羁绊可成长？

服务端会先按所选赛季加载棋子技能与羁绊详情，再让 LLM 按定义文档扫描和分类。分类结果按“赛季 ID + 实体详情内容指纹”缓存；赛季或详情发生变化时会自然生成新缓存，`refresh=true` 可主动重扫。

## LLM 配置

分类器优先读取专用变量：

```dotenv
TFT_AGENT_MECHANISM_CLASSIFICATION_ENDPOINT=
TFT_AGENT_MECHANISM_CLASSIFICATION_MODEL=
TFT_AGENT_MECHANISM_CLASSIFICATION_API_KEY=
TFT_AGENT_MECHANISM_CLASSIFICATION_MODE=auto
TFT_AGENT_MECHANISM_CLASSIFICATION_TIMEOUT_MS=90000
TFT_AGENT_MECHANISM_CLASSIFICATION_MAX_OUTPUT_TOKENS=8000
TFT_AGENT_MECHANISM_CLASSIFICATION_THINKING_MODE=disabled
```

未设置专用变量时，会回退使用现有的 `OPENAI_BASE_URL`、`MODEL_NAME` / `OPENAI_MODEL`、`OPENAI_API_KEY`，因此正常情况下不需要新增配置。

## 输出约定

接口返回 `type: "mechanism_classification"`，主要字段如下：

- `entries`：过滤到本次问题范围内的模型分类结果；
- `modelOutput`：模型返回的原始 JSON，不做结论覆盖；
- `entry.isGrowth` / `entry.isDevelopment`：模型原始判断；
- `entry.definitionMatchedGrowth`：是否满足“跨回合 + 永久保留”的定义检查；
- `entry.needsReview`：模型主动要求复核，或模型判断成长但跨回合信息不足；
- `classificationMeta`：赛季、模型、提示词版本、缓存和调用用量信息。

定义检查只提示冲突，不修改模型的 `isGrowth` 原判。前端结果卡会同时展示模型判断和定义检查，并可展开查看完整原始 JSON。

人工复核标签写入提示词并按赛季限定，不在本地代码中覆盖模型输出。提示词版本参与缓存键，案例更新后会自动绕过旧分类缓存。
