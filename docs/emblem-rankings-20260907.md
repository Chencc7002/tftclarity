# 转职强度查询

日期：2026-09-07；2026-09-08 补充自由聊天接入。已集成到 TFTAgent 本地工作区，完成回归和浏览器验证，尚未部署生产。

## 产品行为

- 入口：工具与收藏 → 全部工具 → 装备分析 → 转职强度查询。
- 默认展示可合成转职，支持金铲铲、金锅锅、全部转职筛选。
- 展示合成配方、平均名次、前四率、登顶率和样本数；可切换排序，低样本始终排在后面。
- 展开卡片按需查询三个常见携带者，复用已有单装备定阵的携带者聚合，按携带样本排序，保留负提升携带者。
- 统计限定至少持有一个转职的对局，队列和版本来自服务器赛季上下文；当前仅支持正式服。
- 合成配方兼容 S18 英文装备 ID 和旧数字 ID；目录外、不可获得、异常大样本分布和非安全整数总数不进入榜单。

## 实现边界

Quick Task 通过注册的 `emblem_rankings` / `emblem_carriers` 工具与已有 ExecutionPlanExecutor 执行，校验证据，返回执行轨迹。不调用 LLM，不增加 Skill 或执行运行时。新能力声明要求 `emblemQuery` 约束，避免抢占原有装备携带者能力匹配。

ReAct 自由聊天已接入同一组注册工具和共享查询服务。用户可以问“金锅锅转职按平均名次排前三”“斗士和裁决使前四率差多少个百分点”“斗士纹章谁最常带”。Agent 获得结构化原始统计、样本标记、指标领先者和确定性计算的两两差值；回答只能作描述性比较，不能把相关性称作合成收益。结果区复用快捷工具排行榜；携带者复用已有 `item_carrier_rankings` 序列化和卡片。

复用边界：此前指定英雄的装备/转职排行榜来自 `unit_builds`，衡量该英雄的条件表现；全局转职榜来自 `items`，限定至少有一个转职的对局，统计总体不同。共用名次统计计算、排序基础能力、装备携带者聚合、查询规划和证据执行链；保留两种统计总体，避免用全局表现冒充英雄适配性。

模型参数严格校验：仅接受合法材料、指标、段位、天数和数量范围；赛季、版本、队列由服务器注入。指定装备 ID 必须有本轮目录解析或排行榜证据。历史对话可以提供实体线索，但不能充当本轮统计证据。携带者结论接受本轮 `emblem_carriers` 证据；装备效果仍需独立 `item_details`。样本数要求完整整数，避免“万”等缩写触发原有数字证据校验。

先通过 Quick Task/ReAct 离线结果等价验证，再在本地默认开放。设置 `TFT_AGENT_REACT_EMBLEM_RANKINGS=off`（运行时选项 `reactEmblemRankings: false`）可隐藏新聊天工具，原有装备路径与快捷查询保留。新指导信息仅在工具可用时加入提示词，原有提示词冻结基线不变。部署时可使用该开关控制启用。

核心模块为 `src/core/emblem-rankings.js`；前端展示位于 `src/app/small-window-ui/emblem-rankings.js` 和同名 CSS。源数据依赖现有 MetaTFT 客户端及官方装备目录。显示时间是本次查询完成时间，不是来源发布或样本截止时间。
