## 本轮确认的产品要求

Skill 要明确告诉模型去调用工具，不能只约定最终回答的栏目，也不能只说
“根据已取得的数据解释”。工具提供装备、阵容和站位，Skill 指导获取并解读，
模型不能自行创造或修改推荐方案。

| 内容 | Skill 中明确要求 | 返回后如何处理 |
| --- | --- | --- |
| 英雄身份 | 按运行时要求调用 `entity_catalog_query` | 复用已解析的身份；歧义时澄清，不猜 ID |
| 装备 | 调用 `unit_builds` | 保留工具返回的组合、顺序和统计；解释须有依据，不自行换装或重新排名 |
| 阵容 | 调用 `comps_rankings`，使用允许的英雄筛选 | 只呈现返回且包含目标英雄的阵容，不自行组队、替换成员或认定主 C / 主坦 |
| 站位 | 对已取得的阵容调用 `composition_tactical_details` | 参数严格来自 `tacticalDetailQueryPlan`；展示返回的行列，不凭经验重排 |
| 解读依据 | 缺少解释所需知识时，在权限和预算允许下调用 `semantic_search` | 只使用验证有效的对应知识；无机制依据就不编造因果解释 |
| 什么时候考虑玩 | 使用一般条件：拿到推荐装备，或者来牌多、升星顺 | 不能声称已经知道玩家的装备和来牌；不扩展为搜牌、升级或实时局面决策 |

本轮有效且范围一致的证据可以复用，无须为了完成清单重复查询。工具不可用、
查询失败或字段缺失时，应说明具体缺口并保留已有结果，不由模型补造推荐。

## 与既有运行时的关系

这些是方法指引，不是额外的执行器或硬编码调用队列。调用仍通过原有 ReAct
`call_tool` 动作，服从工具 schema、server-scoped 参数策略、确定性
`nextActionAffordance`、必须执行的后续动作、澄清、预算和 finish 验证。
Skill 不能绕过要求立即结束的运行时指令，也不能把不在有效工具集合内的工具
变成可调用。

当前 legacy broad-unit-play 生产路径仍只开放原有装备相关工具。Shadow 不会
把这份内容传给模型，因此这次更新不意味着线上已自动查询阵容和站位。
后续需要在新版本离线候选中验证指引，再按既有发布门槛接入生产。

`allowedTools`、facet、数据依赖和 Evidence / completion policy 均未扩大。
`1.0.0` 旧实验定义和 `1.1.0` 第一批收敛内容保留；当前定义使用 `1.2.0`。
结束观测适配器同时识别 `1.1.0` / `1.2.0`，因为二者的事实映射契约相同。
原 PR1C / PR1D 的冻结候选、渲染器、哈希与报告没有修改；旧渲染器不会自动
采用本轮的新指令，后续实验必须明确使用新的候选版本。
