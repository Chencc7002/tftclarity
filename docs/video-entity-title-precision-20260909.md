# 视频检索：按游戏实体约束标题

## 需求与规则

用户明确要求将精确检索从英雄推广到装备、阵容以及其他游戏实体。目标实体必须出现在视频标题中（允许目录中的同义名），简介和标签不能替代标题命中；热度、发布时间和旧版本补充不能绕过实体约束。

当前实现是 `strategy_video_search` → `BilibiliStrategyVideoService` → 现有 MCP 搜索/详情。`docs/react-chat-r1-architecture.md` 中 R1.5 的“B 站仅手动导入本地元数据”描述已落后于代码，本次以现有注册工具实现为准，不新增 Runtime、Skill、工具或工具输入字段。

## 实现

- `src/domain/tft/video-entity-scope.js`：使用服务端提供的当前赛季目录（英雄、装备、羁绊，可选强化符文和阵容记录）及已加载的阵容元数据，识别规范名和别名。不开网络，不查询数据库，不使用 LLM 猜别名，不提升 `fuzzyAliases` 权限。
- 同一实体的别名合并。明确的多个实体默认要求标题全部命中，例如“斗士剑圣”必须同时命中斗士/格斗家和剑圣/易。“或”连接的不同实体按任一命中处理；混合 AND/OR、歧义别名和排除条件暂时标记 `ambiguous`，严格模式不擅自放宽。
- 已登记的阵容名称/别名作为阵容身份匹配，不能仅靠命中其中任意成员通过。未登记的“羁绊＋英雄”组合通过各自实体的 AND 约束匹配；不会由模型编造阵容别名，也不要求标题列出完整八人阵容。
- 标题匹配使用最长已知名称，防止“光明羊刀”同时被当作普通“羊刀”。单字汉字名字采用词边界及星级/主 C 语境判断，避免“轻易”“容易”命中“易”；英文别名采用拉丁词边界。复用通用繁简转换，补全“聖、雲、頂”。
- 严格模式在详情请求之前过滤，详情合并后复查标题；所有版本及跨端补充只能使用通过过滤的候选。标题别名命中不再受旧相关性分数门槛误拦截。排序和原有版本窗口政策保留。
- 匹配范围只通过服务端上下文注入；Quick Task 复用已加载目录，ReAct 复用同赛季请求资源。取消信号在资源加载前后检查。影子模式仅观察现成目录/缓存，不触发额外目录网络刷新。

## 开关与可观测性

`BILIBILI_ENTITY_MATCH_MODE`：

| 值 | 行为 |
| --- | --- |
| `off` | 原有搜索、过滤和排序；不加载实体资源。 |
| `shadow`（默认） | 保留原有结果和 B 站工具调用，额外输出 `entityFilter` 观察记录。 |
| `enforce` | 按实体标题规则过滤；结果不足就少返回，没有匹配就返回空结果。 |

每个生态组的 `entityFilter` 包含识别状态、实体身份、命中的查询别名、AND/OR 关系、接受/排除数量及视频 ID、返回结果中不满足范围的视频 ID、详情标题更新后的排除数量。严格模式的视频证据包含 `titleEntityMatch`。

目录加载失败或实体歧义在严格模式下返回空结果并带稳定警告，不能静默恢复宽泛结果。`off` 可直接回滚，无数据迁移。初版只实现影子模式；用户随后明确授权测试并上线，生产配置将在候选镜像的真实检索对照通过后切换至 `enforce`，代码默认值仍保留 `shadow`。

## 范围限制与上线检查

这是基于**已有目录**的通用实体匹配，不代表能识别所有未收录俗称。`unscoped` 表示未找到已知实体，继续原有广泛检索；不能将该状态宣称为“精确匹配成功”。未收录的阵容外号需要先补入可信实体/阵容目录。强化符文需调用方提供同赛季目录，当前通用目录未提供时不会凭空补全。

目前没有追加搜索请求或扩张召回额度：严格过滤可能只留下少量结果，即使 B 站其他页还有相关视频。这优先满足精度要求，不承诺召回完整。标题命中只证明元数据相关，不能证明视频正文讲解正确、标题为主要主题或版本内容有效。

上线前应以影子日志检查英雄、装备、羁绊、命名阵容和组合阵容各类覆盖率，单独检查 `unscoped`/`ambiguous` 与被排除标题，并审阅真实 B 站候选的误杀情况，再将配置切至 `enforce`。本轮验证使用本地固定候选，不作真实 B 站效果验收结论。
