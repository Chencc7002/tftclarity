# 阵容趋势简述与结论正文显示修正

用户问题：简述今天阵容趋势：列出最有潜力的阵容和最卷的阵容。

## 原因

原校验将工具返回的上升、下降、选取率三个榜单视为回答必须全部覆盖的内容，因此把没有复述下降榜单的简述判为失败。同时，名称逐字匹配没有忽略间隔符两侧的空格，导致截图中语义相同的阵容名称未匹配到上升和选取率榜单。此处三个拒绝原因均不能证明回答的数据错误。

## 修正范围

- 阵容名匹配统一空白、Unicode 兼容字符和常用间隔符，保留英雄与阵容名称本身。
- 普通趋势概览的榜单覆盖差异记录到 `answer_coverage_observed`，不再单独导致拒绝、重试或降级。仍须提及至少一个证据中的阵容；明确指定上升或下降方向时，继续要求对应方向的结果。
- 保留统计、引用及历史证据校验；`trendCoverageMode: "strict"` 可在内部调用中恢复原来的全部榜单覆盖门槛，便于比较和回退。
- 仅在已取得当前 `comps_trends` 证据时添加 `composition-trend-summary-guidance.v1`：先回答用户所问内容，再按需补充其他榜单。无关查询与单英雄指导实验的固定提示基线保持不变。
- 聊天优先显示 `modelConclusion.answer` 正文，删除重复的系统替代结论及“系统证据结论”“模型原始结论”“结论”等标题。没有模型正文时显示现有证据回答。反馈按钮、证据区及后端诊断信息继续保留。
- 正文渲染保持 HTML 转义；只去除通用结论标签，保留有实质内容的段落、列表及小标题。

## 验证

- 截图同款问题和回答的循环回归：一个工具调用后正常完成，没有 `decision_rejected`；下降榜单仅形成观察事件。
- 定向回归：279 项通过。
- 标准主回归：1476 项通过、7 项跳过；1 项原有 README 导航检查失败，与本次改动无关。
- 标准集成回归及离线评测通过，具体日志见 `.cache/partial-evidence-*-final.log`。
- 使用实际结论渲染函数及样式，在浏览器中检查 560px 和 360px 容器：正文仅一份、无重复标题及横向溢出。
