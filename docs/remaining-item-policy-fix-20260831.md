# 条件补装：已携带特殊装备与普通待补装备

## 根因

上一版把“只含普通装备”作用于整套出装，导致锁定斗转等特殊装备时被判定为冲突。实际补装需求是保留已携带装备，只限制待补的装备。

实测还发现两个相关入口问题：S18 缺少“斗转”的精确别称（S17 已有）；快捷条件查询在两件装备仅识别出一件时，可能静默忽略另一件。修改统计天数时，模型还可能换用不带携带条件的批量工具，让结果区偏离补装问题。

## 实现

- `itemPolicyScope=remaining_items`：类别限制只作用于未锁定的装备槽；携带装备仍必须属于当前可用目录。按数量扣除锁定装备，不能借相同 ID 放行额外特殊装备。
- 用户明确要求整套/全部三件都普通时使用 `all_items`，保留原冲突校验，不偷偷移除斗转。
- 会话保存范围；查询缓存按范围隔离。结果区显示“待补装备：普通装备”，结论证据携带同一范围。
- S18 的 `DA_18_EmblemBrawler` 添加斗转别称；快捷入口逐项校验已填写装备，未识别时进入现有确认流程，保留模糊判断。
- 单英雄类别修改或补装续问不能执行无阵容上下文的 `unit_builds_batch`。在现有 ReAct 校验入口拒绝并要求改用 `unit_builds`、保留携带条件、重新获取当前实体证据。没有将历史证据当作当前证据。
- 仅修改统计天数时，沿用当前补装上下文中最近一次用户明确指定的类别范围；不使用助手回答中的装备名称或类别来覆盖用户条件，也不把推荐的第三件加入锁定列表。没有为此新增会话状态存储。
- 原有默认补装范围和阵容批量工作流仍保留；没有新增工具参数或第二运行时。
