# 候选点击浏览器验收

日期：2026-09-06。使用 Codex 内置浏览器访问独立本地服务 `http://127.0.0.1:17461/`。

## 范围

服务由 `scripts/entity-choice-browser-fixture.mjs` 启动，候选模型和技能内容使用固定测试数据；实际前端、HTTP 流、注册工具、ReAct、会话存储及 Evidence 校验不替换。本次验证点击交互，不评估真实模型准确率或线上数据。

## 结果

- 默认窄屏聊天输入“法师姐姐的技能是什么”，显示“娜美”“卡尔玛”两个名字按钮；实际截图确认布局可见、无内部 ID 或伪置信度。
- 点击第二个候选“卡尔玛”，无需再次输入或点击发送。聊天显示选择的名字，后端收到“卡尔玛的技能是什么”，自动重新查询目录和详情并回答。原按钮在运行中和完成后均禁用。
- 宽屏 1280×800 验收发现结果面板使用 `renderCoachAnswerResult`，遗漏了候选按钮。已在该分支补上候选和澄清建议渲染，保留原回答显示。
- 修复后重新打开页面，提交“扇子姐姐的技能是什么，只看四费英雄”。结果面板出现可用的单候选按钮；实际点击后，聊天显示“卡尔玛”，后端收到“卡尔玛的技能是什么，只看四费英雄”，完成目录与详情查询并回答。
- 修复后的页面控制台未发现 error；旧候选按钮不可用。验证结束恢复默认浏览器尺寸。

回归：`test/entity-confirmation.test.js`、`test/small-window-ui.test.js` 共 75/75 通过。新增测试执行实际结果面板渲染函数，防止聊天候选存在而结果面板丢失。

日志：`.cache/entity-choice-browser/events.jsonl`；测试日志：`.cache/entity-choice-panel-tests.log`。最初诊断脚本监听请求 data 事件使输入流过早被消费，已移除并改为记录响应；这一测试脚本问题不涉及生产代码。

浏览器验收期间曾因账户额度被自动审批中断，用户继续后恢复并完成以上复测。未修改生产开关或部署。
