# 名称容错：全目录与历史输入验证

日期：2026-09-06。本阶段增加可复现验证工具，没有修改运行时纠错算法、生产开关或既有服务。

## 数据与来源

它们是历史目录；`patch=current` 字符串不能证明今天仍然有效。另一个名为 `match-display-live-catalog.json` 的 lookup 快照内部元数据实际为 PBE，生成时间为 2026-08-16，没有把它冒充当前正式服目录。

第二份目录指纹：`256215839e553b84bd8298a86daf2799be41709771ffec70ac1ffb47bc9117e1`。

旧 `.cache/small-window-cache.json` 无法解析为合法 JSON，已跳过；没有截取、修复或重写文件，也没有将其中内容纳入统计。

## 验证方法

新增 `eval/entity-names/catalog-audit.js` 和 `scripts/audit-entity-name-catalog.mjs`：

1. 从指定赛季缓存导出仅含名称和目录字段的快照，附目录哈希；其他赛季没有自动回退。
2. 从完整目录中文正式名及别名生成删除、重复、相邻交换、同音替换压力样本。
3. 对每条名称分别运行 off、shadow、suggest，验证 shadow 输出等价以及精确结果不被覆盖。
4. 如果生成结果本身已是一个精确名称，单独报告碰撞，不当作原对象纠错的准确率样本。删除后只剩一个字的也不计入可评估集合。
5. 对日志只提取已有实体工具调用的名称，去重并保留出现次数。历史模型返回的实体不是正确性标签。
6. 压力样本、本地验收与生产导出使用独立来源字段。没有人工标签的真实输入准确率必须为 null。

压力样本是自动构造的工程测试，**不是独立真实用户 holdout，也不是线上准确率**。名称候选的分数和样本频率均不能替代语境标注。

第一次主目录运行中，候选计算耗时 p50 约 0.70ms，p95 约 1.04ms；仅包含本机候选模块计算，不包含目录加载、模型请求或网络时间，后续运行随机器负载变化。

两个前五未完全覆盖的样本是删除造成的短名“光甲”和“光子”。多个光明装备及普通装备都在一个字距离内，候选数超过五个。其他典型歧义包括：

- “阿卡丽”删除“卡”得到“阿丽”，同音的“阿狸”会排第一，但原目标仍在候选中。
- “凯尔”删除“尔”得到单字“凯”，不能安全地自动认定。
- “光甲”可能来自不同光明装备简称，单靠名称不足以唯一判断。

没有为这些观察结果增加专属别名或调参刷分。保留第一阶段所有新候选必须确认的行为；不把 306 条生成样本中的零错配解释成真实环境零错误。

按生成方式拆分主目录 Top-1：同音替换 357/357，插字 522/524，相邻交换 513/522，删字 352/422。当前最明显的弱项是删字后的短名称歧义；这仍是压力样本分组结果，不是玩家输入分布。

## 历史输入回放

主缓存有 12 条本地验收请求，其中 4 条没有可提取的实体目录证据，抽取去重后 4 个实体名称。复核缓存有 15 条请求，其中 1 条没有目录证据，抽取去重后 5 个名称。

这些名称已通过既有精确或人工模糊别名路径覆盖，当前回放没有新增的 `not_found` 候选收益。两个缓存包含重复验收场景，不能合并宣传成 27 个独立用户样本。

这也暴露观测边界：如果模型在调用目录前就改写名称，或根本没有调用目录，目录候选评测看不到原始识别失败。后续需要对原问题、提取的名称和人工期望对象做端到端标注，不能仅统计工具候选命中。

## 重复执行

在 Node >= 20 环境运行：

```powershell
npm run audit:entity-names -- --cache=.cache/remaining-item-cache.json --season=set18-live
npm run audit:entity-names -- --cache=.cache/artifact-local-cache.json --season=set18-live --output=.cache/eval/entity-name-artifact-audit
```

输出包括 `snapshot.json`、`observed.json`、`report.json`，默认在 `.cache/eval/entity-name-catalog-audit/`。原始缓存只读。名称回放文件仅允许写入 `.cache` 子目录，避免将潜在用户输入提交进仓库；不会保存用户身份、会话 ID、完整原句或整份回复。

命令退出码验证协议不变量；召回率和误差作为报告项，不人为设置未经验证的生产上线阈值。错误赛季、快照哈希不一致、缺失目录、错误样本或目录外标签会失败。

验证结果：`test:ci:main` 1415 passed / 7 skipped；`test:ci:integration` 235 passed / 1 skipped；`eval:agent` 50/50；`eval:entity-names` 41/41。全目录审计不变量全部通过。新增五项审计测试覆盖数据投影、赛季隔离、哈希校验、历史结果不得变标签、名称碰撞统计及非法标签拒绝。

## 当前决定

全目录压力测试与历史验收回放已经完成；真实用户阶段尚未满足：缺少今天的权威目录快照和独立人工标注的用户失败输入。因此报告的 `productionAccuracy=null`，发布判断为 `hold_requires_current_catalog_and_independent_labeled_user_samples`。

生产仍默认 `off`；没有部署或重启。本次不开放自动纠错。下一步是用当前服务的权威目录和用户原始错字样本做独立验证，再在可追踪的环境开启 shadow，之后才推进候选确认试用。
