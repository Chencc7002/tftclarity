## 1. 产品简述

tftclarity 是一款面向中文用户的公开、非商业《云顶之弈》数据分析、对局复盘与学习工具。用户可以使用英雄、装备、羁绊和阵容的中文名称及社区常用俗称提出自然语言问题，产品会将问题转换为确定性的结构化查询。用户也可以提交Riot ID，查看当前可取得的近期对局和终局棋盘，或者把选定玩家组织成小型 Player Pool，进行描述性分析和对比。

产品会展示聚合阵容与英雄装备统计、近期对局证据、Player Pool 样本统计、多个候选方案，以及明确的低样本或数据过期提示。可选 AI 功能只负责解释已经验证的证据，不能创建、替换或修改底层统计。

tftclarity 用于赛前参考、赛后学习和长期版本理解。它不会读取当前对局状态，不会提供动态实时指令，不会侦察对手、识别被隐藏的玩家，也不会创建非官方 MMR/ELO 系统。

## 2. 产品完整说明

中文 TFT 玩家通常需要先把口语化问题转换成官方名称和筛选条件，再浏览多页统计表格，才能得到有用结论。tftclarity 希望缩短这条路径并降低cognitive load,降低新手玩家使用数据检索器的门槛。

用户可以提出例如以下问题：

- “霞当前版本最稳的三件装备是什么？”
- “比较这个英雄的无尽之刃和破防者。”
- “显示当前热门阵容。”
- “这个版本有哪些阵容正在上升？”
- “保持同一阵容和段位条件，比较另一件装备。”

tftclarity 会解析实体名称和别名，应用透明的筛选条件，查询聚合 TFT 数据，在本地计算或校验指标，并返回带有备选方案的简洁结果。结果会显示实际采用的查询范围、数据源新鲜度、样本量、平均名次、前四率、登顶率，以及证据较弱时的风险提示。

核心排名和筛选链路是确定性的。LLM 只用于受控的自然语言解析，或根据经过验证的证据包生成简短说明。LLM 输出会与结构化结果进行校验，不能改变数值证据。

当前产品使用第三方 MetaTFT 数据、基于 OP.GG 的玩家查询，以及官方或公开的 TFT 静态数据源。取得 Production API 权限后，我们计划在 Riot 已支持的范围内替换第三方玩家与对局查询，使用 Riot 对局和联盟数据建立第一方聚合，并在 Riot 要求账号授权的功能中实现 Riot Sign On。

## 3. 玩家价值与差异化

- 支持中文自然语言、社区俗称和历史别名。
- 从一个问题直接得到范围明确的统计结论。
- 提供多个选择，而不是规定唯一操作。
- 明确展示样本、筛选条件、数据源、新鲜度和风险提示。
- 使用确定性统计，并提供可选的、基于证据的 AI 解读。
- 支持保留短期匿名上下文的连续追问。
- 根据访客提交的 Riot ID 提供近期对局和终局棋盘复盘。
- 提供用户自选 Player Pool、覆盖率、样本门槛、分享码复制和描述性对比。
- 产品定位是学习工具，而不是实时游戏自动化或侦察工具。

## 4. 目标用户

主要用户是希望完成以下任务的中文 TFT 玩家：

- 进行赛前准备；
- 从过去的对局中学习；
- 理解版本级环境趋势；
- 比较英雄装备选择；
- 无需学习 API 名称或英文术语即可探索热门阵容；
- 查看当前可取得的近期对局和终局棋盘；
- 组织一个规模较小、明确选定的玩家样本，并比较观察到的阵容偏好。

产品公开提供服务，不要求注册 tftclarity 账号。当前尚未使用 Riot Sign On。访客可以输入本人或其他玩家的 Riot ID，但输入 Riot ID 并不能证明访客拥有该账号。我们请求 Riot 审核这一现有流程，并为 Riot 认定必须进行账号授权的功能申请 RSO 权限。

## 5. 审核人员体验流程

### 流程 A — 英雄装备推荐

1. 打开 <https://tftclarity.cn/>。
2. 输入中文英雄出装问题，例如：`霞当前版本最稳的三件装备是什么？`
3. tftclarity 识别英雄和查询意图。
4. 服务端应用页面可见的段位、版本、样本、装备范围和时间窗口条件。
5. 结果区显示排名第一的完整出装和备选方案。
6. 每项结果显示样本量、平均名次、前四率、登顶率、数据源新鲜度和风险提示。
7. 用户可以修改筛选条件或继续追问。

**玩家价值：**把一个口语化中文问题转换成透明、有证据支持的静态参考。

### 流程 B — 装备对比

1. 从英雄出装结果开始，或者直接输入比较问题。
2. 在相同英雄和上下文中比较两件装备。
3. 产品保留英雄、版本、段位和阵容条件。
4. 产品分离互斥的完整出装样本，并报告样本重叠情况。
5. 如果差异太小或样本不足，产品会明确拒绝指定胜者。

**玩家价值：**解释取舍，不隐藏不确定性，也不规定唯一选择。

### 流程 C — 阵容排行与趋势

1. 查询当前阵容排行，或选择阵容排行快捷入口。
2. 产品显示所选范围内的聚合阵容表现和热度。
3. 用户可以展开阵容，并继续查询其中英雄的装备。
4. 在有数据时，趋势视图会比较版本快照；历史不足时会明确标记，而不是编造趋势。

**玩家价值：**使用聚合、非特定玩家统计帮助用户学习版本和进行赛前准备。

### 流程 D — 多轮条件细化

1. 完成任一受支持查询。
2. 继续追问，例如“保持同一阵容，只看大师及以上”或“比较另一件装备”。
3. 产品复用短期匿名上下文，并显示条件来自当前输入、对话、用户偏好还是系统默认值。
4. 用户可以随时清空对话。

**玩家价值：**降低复杂筛选的使用门槛，同时让实际采用的查询范围保持可见。

### 流程 E — 法律与数据透明度

1. 页面底部持续显示 tftclarity 是独立项目，未获得 Riot Games 认可。
2. 页脚和设置面板提供 Privacy Policy 与 Terms of Service 链接。
3. 设置面板显示完整 Riot 声明和 Riot 开发者政策链接。
4. 查询结果会标明当前数据源，并显示新鲜度或缓存风险提示。

### 流程 F — Riot ID 对局复盘

1. 打开“战绩、Pool 与复盘 → 对局可视化与复盘”。
2. 输入 PBE 或 NA Riot 游戏名和 Tag。
3. 后端通过当前配置的数据提供方解析目标玩家，并返回最多 10–20 场当前可取得的近期对局。
4. 用户可以展开一场对局，查看名次、终局棋子、装备、羁绊、强化符文及数据提供方支持的其他事实。
5. 可选 AI 复盘只接收已经取得的结构化证据，不得编造数据提供方未返回的逐回合经济、商店、站位或决策过程。

**玩家价值：**使用可见证据支持赛后反思，而不是提供实时对局指令。

### 流程 G — Player Pool 与对比

1. 每位访客最多创建两个 Pool，每个 Pool 包含 1–15 个 Riot ID；也可以通过八位分享码复制另一个 Pool 的当前成员名单。
2. 每个 Pool 显示所选样本的对局覆盖、版本分布、阵容使用、平均名次、前四率、登顶率和代表性终局棋盘。
3. 只有在赛季、版本、玩家覆盖和对局数量门槛允许时，两个 Pool 才能进行可比较分析。
4. 不满足门槛时，产品只并列展示观察结果，禁止得出某个 Pool 更强或更弱的结论。

**玩家价值：**让学习小组或分析者研究一个有明确边界的自选样本，而不会把它表述为全服强度、因果关系或非官方评分。

## 6. 当前与计划中的数据源

### 当前产品

- 使用第三方 MetaTFT 聚合统计展示阵容和英雄装备结果。
- 当前 PBE 近期对局流程使用第三方 MetaTFT 玩家对局查询。
- 当前 NA 近期对局流程使用基于 OP.GG 的玩家解析与对局查询。
- 服务端标准化事实库保存 Riot ID、对局摘要、终局棋盘、Pool 成员关系、覆盖信息和描述性 Pool 统计。
- 使用官方或公开 TFT 静态目录和资源维护名称、装备详情和图标。
- 使用本地确定性计算、筛选、标准化和校验。
- 可选 OpenAI-compatible 服务仅用于受控解析或基于证据的解释。

### 计划使用的 Riot 数据

- `tft-league-v1`：在获准区域发现允许使用的高段位玩家种子。
- `tft-match-v1`：取得对局 ID 和对局详情，用于离线聚合。
- `account-v1` 以及适用的 TFT 账号/资料接口：在 Riot 批准的范围内解析所提交的 Riot ID，并支持账号关联流程。
- Riot Sign On：验证玩家身份，并在 Riot 要求时把个人历史功能限制为已授权账号本人。
- Data Dragon/TFT 静态数据：维护版本化英雄、装备、羁绊、队列和资源目录。

当前第三方近期对局流程仅支持 **PBE 和 NA**。计划中的 Riot 数据首期范围是 **NA1**，以及 Riot 支持的亚洲平台，例如 **TW2、SG2、JP1 和 KR**；最终范围取决于 Riot 批准的接口、路由值、RSO 权限和上线区域。由于 Riot 公共 Developer API 不提供中国大陆平台路由，产品不会声称覆盖中国大陆服务器。

## 8. 游戏公平性与政策边界

tftclarity：

- 提供独立于当前实时对局状态的静态聚合信息和赛后对局事实；
- 用于赛前准备、赛后学习和版本分析；
- 提供多个选择，保留玩家的自主决策；
- 不检查 League/TFT 客户端或实时棋盘；
- 不根据当前游戏操作改变推荐；
- 不提供“现在必须这样做”的指令；
- 不侦察对手或预测其下一步行为；
- 不识别或分析被游戏刻意隐藏的玩家；
- 不创建非官方 MMR 或 ELO；
- 不支持赌博或投注；
- 当前通过第三方数据提供方支持访客提交 Riot ID 查询和用户自选 Player Pool；
- 不把输入 Riot ID 视为账号所有权证明；
- 请求 Riot 对现有功能进行审核并授予 RSO 权限，以便在需要时把个人历史限制为已认证账号本人；
- 如果 Riot 认定非本人玩家历史或 Pool 流程不在批准范围内，我们会修改、限制或移除相关功能。

产品不会把玩家历史用于对局中的对手侦察、隐藏玩家识别、非官方 MMR/ELO、就业、信贷、赌博或其他会产生重大后果的画像。Player Pool 是有明确边界的描述性样本，不是全服排行榜。

## 9. AI 用途与保护措施

AI 是可选功能，仅用于：

1. 把口语化中文映射到受控查询结构；
2. 对已经包含验证结果的证据包进行总结。

排名、筛选、指标和资格规则均由确定性代码处理。AI 输出不能修改样本量或表现指标。生成的解释会与证据进行校验；如果校验失败或模型服务不可用，产品会使用确定性模板降级，并明确标注结果来源。

## 10. 隐私与安全摘要

- 不要求注册产品账号。
- 对局复盘和 Player Pool 功能接收 Riot 游戏名、Tag 和区域，并处理当前可取得的玩家及近期对局事实。
- 当前 NA 数据提供方返回的 PUUID 只会在配置服务端加密密钥时以加密形式保存，否则不会持久化。
- Pool 名称、成员 Riot ID、所选环境、所有者匿名范围、可选分享码和标准化对局事实保存在服务端。获得分享码的人可以把当前成员名单复制到一个独立 Pool。
- 使用签名匿名 `tft_visitor` Cookie 隔离访客范围并执行公开访问配额。
- 查询快照最多保留 30 天，用于反馈完整性、质量调查和安全处理。
- 用于连续追问的结构化记录最长保留 7 天。
- 可选反馈只保存相关查询和标准化结果上下文。
- 使用 HTTPS、HTTP-only Cookie、范围化标识符、限流、服务端密钥和访问控制保护服务。
- 隐私请求通过 `tftclarity@outlook.com` 处理。

详见公开的 [Privacy Policy](https://tftclarity.cn/privacy) 和 [Terms of Service](https://tftclarity.cn/terms)。

## 12. Portal 字段可直接使用的简短回答

### 你的产品做什么？

tftclarity 是面向中文 TFT 玩家的公开数据分析、对局复盘与学习工具。它把中文自然语言问题和社区俗称转换为确定性的阵容及英雄装备统计查询。访客也可以提交 PBE 或 NA Riot ID，查看当前可取得的近期对局与终局棋盘，并把选定玩家组织成带有覆盖率和低样本门槛的小型 Player Pool。可选 AI 只解释已经验证的证据，不能创建或修改事实与统计。

### 你将如何使用 Riot API？

我们计划使用 `tft-league-v1` 获取获准的排位玩家种子，使用 `tft-match-v1` 获取对局 ID 和对局详情，使用 `account-v1` 及适用的 TFT 账号/资料路由解析 Riot ID，并使用 Data Dragon/TFT 静态数据维护版本化目录和资源。我们同时申请对个人对局历史进行 RSO 评审。服务端管线将执行限流、重试、去重、标准化、分类和聚合。如果 Riot 要求该边界，我们会把个人历史功能限制为已授权账号本人。

### 当前数据源是什么？

当前产品使用第三方 MetaTFT 聚合数据和 PBE 玩家对局数据、基于 OP.GG 的 NA 玩家查询与对局数据，以及官方或公开的 TFT 静态数据源。产品保存标准化对局事实，用于近期对局复盘和用户自选 Player Pool。Production API 权限将用于把已支持的账号、对局、联盟和聚合流程迁移至 Riot 服务。Riot 对产品的批准不会被视为对无关第三方数据集的使用授权。

### 产品是否使用实时游戏数据？

不使用。tftclarity 不读取当前游戏状态，不检查实时棋盘，不跟踪对手，也不根据对局中的操作动态改变推荐。它提供赛前准备、赛后学习和版本理解所需的静态聚合参考与赛后事实。

### 产品是否需要 RSO？

我们申请 RSO 评审和访问权限。当前产品接受访客提交的 Riot ID 并显示当前可取得的近期对局，但尚未验证账号所有权。我们理解 Riot TFT 政策把本人玩家统计和个人对局历史训练工具列为 RSO 使用场景。若 Riot 要求，我们准备把个人历史功能限制为已授权账号本人，并修改或移除非本人历史和 Player Pool 流程。请告知哪些现有流程可以保持公开，哪些必须经过 RSO 授权。

### 如何保护 API Key？

Production API Key 只会保存在服务端环境变量或密钥管理系统中，由后端采集服务通过 HTTPS 使用。密钥不会出现在浏览器代码、源代码仓库、日志或分发的二进制文件中。采集器会执行 Riot 限流、遵守 `Retry-After`，并从错误信息和运维接口中移除敏感信息。

## 14. 审核人员测试步骤

1. 访问 <https://tftclarity.cn/>。
2. 确认页面显示独立项目声明以及 Privacy/Terms 链接。
3. 提交 `霞当前版本最稳的三件装备是什么？`。
4. 查看首选出装、备选方案、样本、表现指标、数据源和风险提示。
5. 在保留英雄上下文的情况下继续提交装备对比问题。
6. 提交 `当前版本热门阵容排行`。
7. 打开设置，检查 Riot 声明和法律链接。
8. 打开“战绩、Pool 与复盘”，输入审核说明中提供的 PBE 或 NA 测试 Riot ID，并展开一场近期对局。
9. 打开准备好的审核 Pool，检查覆盖和样本提示；如果已准备两个兼容 Pool，则打开对比。
10. 访问 <https://tftclarity.cn/privacy> 和 <https://tftclarity.cn/terms>。

产品界面主要使用中文，因为目标用户是中文 TFT 玩家。英文申请文件及随附截图说明会帮助审核人员理解每一步操作。
